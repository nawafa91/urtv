# تطوير نسخة nawafa91/urtv المستقلة

## مصادر المحتوى

المصدر المشترك في `config/repository.json` يثبت الصور والخطوط على معرّف commit كامل،
ولا يقبل مولّد الصفحات أو Gradle فرعًا متحركًا. يقرأ التطبيق تحديثاته من بيان قناة
`content-stable` فقط، لا من `master`. تفاصيل التوافق والبصمة والتراجع في
[جاهزية TCL والتحديث المستقر](TCL-READINESS.md).

بعد تعديل القالب شغّل `python3 src/build.py` وضمّن `dist/` في التغيير.
التحديث كل 6 ساعات يخص صفحة شاشة التوقف فقط؛ بطاقة الرئيسية مضمّنة، وAPK لا يُحدَّث تلقائيًا.
غياب إصدار مستقر منشور يبقي النسخة المضمّنة عاملة. إجراءات GitHub لا تنشر شيئًا.

## التوقيع والهوية

حُفظت أسماء الحزم `sa.urtv.screensaver` و`sa.urtv.home` ومزوّد الإعدادات وصلاحية
`READ_CONFIG` لحماية توافق البيانات الحالي. يتطلب عمل البطاقة أن يُوقّع التطبيقان
بالشهادة نفسها. لم تُحذف تفضيلات مستخدم أو بيانات جهاز.

أُزيل المفتاح القديم من الشجرة الحالية؛ يظل موجودًا في سجل المشروع السابق، فلا يُعد
مفتاحًا خاصًا آمنًا. لا يُستخدم لبناء النسخة المستقلة. لم يُنشأ مفتاح بديل.
من دون متغيرات التوقيع ينتج `gradle -p android assembleRelease --no-daemon` ملفين غير موقّعين.
إجراءات GitHub تبنيهما كملفات تحقق فقط، بصلاحية قراءة ودون نشر إصدار.
لا تستخدم `assembleDebug` في هذه المرحلة؛ قد ينشئ أندرويد مفتاح تطوير تلقائيًا.

**قبل إنشاء مفتاح جديد، يجب اعتماد خطة الانتقال.** شهادة جديدة لا تحدّث التطبيقات
القديمة ذات الشهادة المختلفة تثبيتًا مباشرًا، حتى مع بقاء أسماء الحزم. سكربت التثبيت
يتوقف عند التعارض ولا يحذف التطبيق. لا توجد في هذه التهيئة آلية لنقل بيانات التطبيق
القديم إلى شهادة جديدة؛ يلزم تصميم انتقال صريح، أو اعتماد أسماء حزم منفصلة للتثبيت
المتوازي إذا كان ذلك هو الاختيار لاحقًا. لا تحذف التطبيق القديم لمعالجة التعارض.

بعد موافقة المالك فقط، يمكن تنفيذ الأوامر التالية على جهاز المالك، مع طلب كلمات المرور
تفاعليًا. **هذه تعليمات لاحقة وليست جزءًا من خطوات التهيئة المنفّذة:**

```sh
umask 077
mkdir -p "$HOME/.local/share/urtv-signing"
keytool -genkeypair -storetype JKS \
  -keystore "$HOME/.local/share/urtv-signing/release.jks" \
  -alias urtv-independent -keyalg RSA -keysize 4096 -validity 10000
```

تُحفظ نسخة احتياطية مشفّرة منه. لا يُرفع الملف أو محتواه أو كلمات
مروره إلى GitHub، حتى ضمن الأسرار أو ملفات البناء. يمكن بناء النسخة الموقّعة محليًا
بعد توفير هذه المتغيرات في جلسة آمنة دون تسجيل قيمها:

- `URTV_KEYSTORE_PATH`: مسار مطلق لملف موجود خارج مجلد المستودع.
- `URTV_KEYSTORE_PASSWORD`: كلمة مرور المخزن.
- `URTV_KEY_ALIAS`: اسم المفتاح المشترك للتطبيقين.
- `URTV_KEY_PASSWORD`: كلمة مرور المفتاح.
- `URTV_VERSION_CODE`: عدد صحيح متزايد، أكبر من إصدار كل تطبيق يُراد تحديثه.

يلزم توفير متغيرات التوقيع الأربعة كاملة أو تركها جميعًا غائبة. البناء الموقّع يتطلب
رقم إصدار صريحًا؛ البناء غير الموقّع يستخدم 1 افتراضيًا، ويمكن تعيين الرقم للاختبار.
لا يُستخدم رقم تشغيل GitHub بديلًا عن سياسة ترقيم مستقلة. التحقق بعد التوقيع لاحقًا:
`apksigner verify --print-certs` لكل ملف ومقارنة بصمة الشهادة، ثم التأكد من رقم الإصدار.
لا تنشر الملفات غير الموقّعة في إصدار التثبيت؛ سكربت التثبيت مخصص لملفات موقّعة يعتمدها المالك.

## متابعة الأصل

الأصل: https://github.com/tshi-dev/UrTV . احتفظ بنسبة المشروع ومصادر الصور والخطوط.
عند الرغبة لاحقًا، أضفه كجهة `upstream` للقراءة، مع إبقاء `origin` لنسختك، ثم اجلب
تعديلاته إلى فرع مراجعة وادمج المختار فقط. راجع عند الدمج مصدر المحتوى والتوقيع وعدم
إعادة الحذف التلقائي أو النشر. لا تجعل تحديث الصفحة على أجهزة المستخدمين يتبع الأصل مباشرة.

## التحقق

`tests/run.sh` يجري فحوص البناء والبيانات، واختبارات التهيئة المستقلة، والرفع والمتصفح.
اختبارات المتصفح الافتراضية تفتح ملفات محلية. في البيئة التي تمنع ذلك، يمكن استخدام
نسخة HTTP المحلية الموثّقة في إعدادات البيئة دون تغيير واجهة التطبيق.
أعد بناء النسختين غير الموقّعتين بالتتابع؛ لا تشغّل بناءين في مجلد المخرجات نفسه بالتوازي.

الواجهة الرئيسية تستهدف API 34 وتستخدم أعلام تصدير المستقبلات على Android 13+،
مع إبقاء الحد الأدنى Android 8. بناء Lint يتوقف عند الأخطاء. يلزم اختبار اسم شبكة
الواي فاي على الجهاز؛ قد يخفيه النظام مع بقاء حالة الاتصال ظاهرة.
